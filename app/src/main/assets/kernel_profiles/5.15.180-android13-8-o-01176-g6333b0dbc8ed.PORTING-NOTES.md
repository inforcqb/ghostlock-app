# GhostLock device profile: OPPO PJA110 / OnePlus Ace 2 Pro (SM8550, kalama)
# Kernel: 5.15.180-android13-8-o-01176-g6333b0dbc8ed

This profile was derived on the live device and is registered in
`app/src/main/assets/kernel_profiles/index.conf`.

## Why `multicast_waiter` and not `tcp_zerocopy`

`compact_waiter = 1` only describes the flat `rt_mutex_waiter` layout
(BTF size `0x58`), which this kernel has. It does **not** make the 6.1
TCP-zerocopy transport valid here. The route inference in
`src/core/profile.h` deliberately sends 5.x to `multicast_waiter`:

```cpp
if (v->kernel_major == 5 && v->mcast_waiter_off > 0) return kRouteMulticastWaiter;
if (v->compact_waiter) return kRouteTcpZerocopy;
```

Driving this kernel through the TCP-zerocopy route reaches the UAF but then
panics in `rb_erase` (`rt_mutex_adjust_pi` -> `sched_setattr`) with a level-1
translation fault, because the forged waiter tree linkage is inconsistent.

## Verification performed

- Vulnerability: `remove_waiter()` still contains `mrs xN, sp_el0` (reads
  `current`), i.e. the CVE-2026-43499 fix is absent. The extractor preflight
  uses the same test.
- All 24 fields shared with the earlier device-proven table match exactly.
- Credential/multicast boundary rules from `PROFILE_SCHEMA_ZH.md` hold:
  `copy_size 176 >= 0xa0`; `caps_offset + caps_count*8 = 72 <= 176`;
  `ref_count = 4 <= 4`; `waiter_off + lock_offset + 8 = 160 <= buffer_size 264`.

## Caveats

- `cred.ref*_image` and `offset.mcast_fake_bss` are the only fields not
  measured directly on this build (their symbols are not exported). They are
  placed by the same relative offsets as the reference 5.15 profile.
- `recommend_shizuku = 1`: run via Shizuku (shell uid, seccomp 0) so W3 is
  unnecessary.
- KASLR is irrelevant to the direct-map alias, so no slide handling is needed.
